# Lesson 01 — Random Variables: From Outcomes to Numbers

## 1.1 Why define a random variable?

Suppose a YouTube-like service recommends one video. The experiment is *show the recommendation and observe what happens*. Its sample space is:

$$ S = \{\text{Click},\ \text{No click}\}. $$

These are outcomes, but our analytics, equations, and predictive models work with numbers. Define a mapping:

$$
X = \begin{cases}
1 & \text{if the user clicks},\\
0 & \text{if the user does not click}.
\end{cases}
$$

**A random variable is a function assigning a number to each possible outcome of a random experiment.** The outcome is uncertain before observation; the definition of the mapping is not.

- Uppercase **$X$** refers to the random variable.
- Lowercase **$x$** refers to a possible value it takes.
- **$P(X=x)$** refers to the probability of that value, when the probability is defined.

In this example, $X\in\{0,1\}$. If a specific user clicks, the observed value is $x=1$.

## 1.2 A random variable is not its probability distribution

The random variable tells us *what is measured*. The distribution tells us *how likely different values are*.

For example, both these models use exactly the same variable, $X=1$ for click and $X=0$ for no click:

- Model A: $P(X=1)=0.10$.
- Model B: $P(X=1)=0.80$.

The variable has not changed; the probability distribution has.

## 1.3 One experiment, several useful variables

From the same recommendation event, we might construct:

- $C$: whether the user clicked (0 or 1).
- $W$: how many seconds the user watched, if a view occurred.
- $L$: whether the user liked the video (0 or 1).

The choice of random variable is driven by the business question. “Did a user click?” and “How much did they watch?” are different modeling questions.

### Check your understanding

**Question:** Is “Clicked” itself a random variable?  
**Answer:** It is an outcome label. We create a *numerical random variable* when we map clicked → 1 and not clicked → 0.

# Lesson 02 — Discrete vs Continuous Random Variables

## 2.1 Discrete = counting separate possibilities

Let $X$ be the number of recommended videos a user clicks among three displayed videos.

$$X\in\{0,1,2,3\}.$$

A user cannot click exactly 1.7 videos. The allowable outcomes are separate counts. This is a **discrete random variable**.

More examples:

- Number of errors in a batch.
- Number of orders per customer.
- Number of API requests received during one second.
- Number of successful trials among 10 trials.

Discrete does **not** always mean the possible set is small. A request count can be any nonnegative integer, potentially with no fixed upper bound.

## 2.2 Continuous = measuring along a continuum

Let $T$ be time spent watching a video, in minutes. A mathematical model may permit:

$$T=2.4,\ 2.45,\ 2.451,\ 2.4517,\ \ldots$$

A real measurement device or database has limited precision, but a **continuous model** treats the underlying quantity as capable of taking values in an interval.

Examples:

- Waiting time until the next API request.
- Network latency.
- Temperature.
- Video watch duration.

**Important subtlety:** A value stored as an integer is not automatically discrete *in the modeling sense*. Latency may be rounded to integer milliseconds even if the underlying time is best modeled as continuous. Conversely, a field represented as a decimal can be discrete if it only supports a fixed set of amounts.

## 2.3 Why does the distinction matter?

For discrete variables, we can ask for the probability of an exact value:

$$P(X=2).$$

For continuous variables, intervals are fundamental:

$$P(2<T<5).$$

Under a continuous probability model, the probability of one exact point is zero:

$$P(T=2.000\ldots)=0.$$

This does **not** mean that a stopwatch cannot read “2.00.” A recorded value usually represents an interval created by rounding or measurement resolution.

### Interview check

**Q:** “API requests per second” and “latency per request”: which is discrete?  
**A:** Request count is discrete; measured latency is generally modeled as continuous.

# Lesson 03 — Probability Mass Function (PMF)

## 3.1 The problem PMF solves

We know $X$, the number of clicks on **two** recommended videos, can take values 0, 1, or 2. But how likely is each number?

For this *toy example*, assume:

1. Each video is clicked independently.
2. Each video's click probability is $0.5$.

These are simplifying assumptions, **not claims about actual YouTube behavior**.

All ordered outcomes are equally likely:

| Video 1 | Video 2 | Number of clicks $X$ | Joint probability |
|---|---|---:|---:|
| No click | No click | 0 | $0.5\times0.5=0.25$ |
| Click | No click | 1 | $0.5\times0.5=0.25$ |
| No click | Click | 1 | $0.5\times0.5=0.25$ |
| Click | Click | 2 | $0.5\times0.5=0.25$ |

Group the rows by their number of clicks:

$$
\begin{aligned}
P(X=0)&=0.25,\\
P(X=1)&=0.25+0.25=0.50,\\
P(X=2)&=0.25.
\end{aligned}
$$

This collection of exact-value probabilities is the **PMF**.

## 3.2 PMF definition and notation

$$\boxed{p_X(x)=P(X=x)}$$

For a discrete random variable, $p_X(x)$ answers: “What is the probability that $X$ equals this exact value $x$?”

Our PMF is:

| $x$ | $p_X(x)$ |
|---:|---:|
| 0 | 0.25 |
| 1 | 0.50 |
| 2 | 0.25 |
| All other values | 0 |

A valid PMF satisfies:

$$
\boxed{p_X(x)\geq0 \quad\text{for every }x}
$$

and

$$
\boxed{\sum_x p_X(x)=1.}
$$

The sum is over **all possible values** of the random variable.

**Sanity check:** $0.25+0.50+0.25=1$.

## 3.3 Probability of an event containing multiple discrete values

**Example A: At least one click.**

“At least one” means 1 or 2 clicks:

$$
P(X\geq1)=P(X=1)+P(X=2)=0.50+0.25=\boxed{0.75}.
$$

**Example B: At most one click.**

“At most one” means 0 or 1:

$$
P(X\leq1)=P(X=0)+P(X=1)=0.25+0.50=\boxed{0.75}.
$$

**Example C: Use a complement.**

“At least one click” is the complement of zero clicks:

$$
P(X\geq1)=1-P(X=0)=1-0.25=\boxed{0.75}.
$$

The complement is often quicker than adding many terms.

## 3.4 Common PMF errors

- **Invalid negative value:** $P(X=2)=-0.1$ is impossible.
- **Probabilities sum to more than 1:** a complete list totaling 1.2 cannot be a valid PMF.
- **Confusing the event with one micro-outcome:** $X=1$ can occur in two different ordered ways, so its probability here is $0.5$, not $0.25$.
- **Treating empirical frequencies as guarantees:** a 25% probability of zero clicks does not guarantee exactly 25 zeros among 100 observed users.

## 3.5 Production interpretation

A product analytics team can estimate a click-count PMF from observed data. But the definition must be stable: “click count within 10 minutes after *exactly two* impressions” is not the same variable as “click count over the whole day.” Device type, ranking position, repeated users, and recommendation quality can change the distribution.

### Interview check

**Q:** If a PMF has $P(X=0)=0.2$, $P(X=1)=0.5$, and the only remaining possible value is 2, find $P(X=2)$.  
**A:** $1-0.2-0.5=\boxed{0.3}$.

# Lesson 04 — Probability Density Function (PDF)

## 4.1 Why a PMF is not the right object for continuous watch time

Let $T$ be a user's watch duration, in minutes. To understand the concept, **assume**:

$$T\sim\operatorname{Uniform}(0,10).$$

This means watch time is uniformly distributed between 0 and 10 minutes. Real watch durations are not generally uniform; we use this model because its graph is a rectangle.

For $0\leq t\leq10$, the PDF is:

$$f_T(t)=0.1\quad\text{per minute}.$$

Outside that interval, its density is 0.

Why 0.1? The complete area must be 1:

$$
\underbrace{(10-0)}_{\text{width: 10 min}}
\times\underbrace{0.1}_{\text{density: per min}}=1.
$$

## 4.2 Probability is *area*, not the height

Suppose we want the probability of watching between 3 and 5 minutes.

$$
\begin{aligned}
P(3\leq T\leq5)
&=(5-3)\times0.1\\
&=2\times0.1\\
&=\boxed{0.20=20\%}.
\end{aligned}
$$

For a general continuous PDF, the graph may be curved. Probability is then the area under that curve:

$$\boxed{P(a\leq T\leq b)=\int_a^b f_T(t)\,dt.}$$

Read the integral as: *accumulate tiny strips of area between $a$ and $b$*. You do not need calculus fluency to understand the idea.

Our rectangle needs only width × height. For example:

$$
P(2\leq T\leq6)=(6-2)(0.1)=\boxed{0.4}.
$$

## 4.3 Why does an exact point have probability zero?

The interval between 5 and 5 minutes has width 0:

$$P(T=5)=\int_5^5 f_T(t)\,dt=0.$$

The density $f_T(5)=0.1$ is **not** the probability $P(T=5)$.

That is the conceptual trap:

- **PMF value:** probability mass at one discrete outcome.
- **PDF value:** density, whose *area over an interval* is probability.

For a continuous random variable, changing an interval endpoint from $<$ to $\leq$ does not change the probability: $P(3<T<5)=P(3\leq T\leq5)$.

## 4.4 Conditions for a valid PDF

A PDF must satisfy:

$$
\boxed{f_T(t)\geq0}
\quad\text{and}\quad
\boxed{\int_{-\infty}^{\infty}f_T(t)\,dt=1.}
$$

**Important interview trap: A PDF can be greater than 1.** Only probabilities are constrained to lie between 0 and 1.

Consider $T\sim\operatorname{Uniform}(0,0.2)$. Its density is:

$$f_T(t)=\frac1{0.2}=5\quad\text{for }0\leq t\leq0.2.$$

Density 5 is valid because $5\times0.2=1$. It also shows why units matter: if time is measured in minutes, the density has units *per minute*.

## 4.5 Production interpretation

An engineer measuring request latencies usually cares about probabilities such as:

$$P(100\text{ ms}<T\leq200\text{ ms})$$

or tails such as $P(T>500\text{ ms})$, not the probability of exactly 173.000000... milliseconds. Before fitting a continuous distribution, inspect rounding, zero values, timeouts, and whether the measurement has a natural lower or upper bound.

### Interview check

**Q:** A continuous PDF has density 4 at $t=0.1$. Is the probability at $t=0.1$ equal to 4?  
**A:** No. A density is not a probability; $P(T=0.1)=0$ for a continuous variable. Density greater than 1 can be valid.

# Lesson 05 — Cumulative Distribution Function (CDF)

## 5.1 Why a CDF exists

A manager asks: “What fraction of users watch for **4 minutes or less**?”

Instead of specifying both interval endpoints, we specify a threshold.

The **CDF** is:

$$\boxed{F_X(x)=P(X\leq x).}$$

It measures *all probability accumulated up to and including $x$*. A CDF exists for **both discrete and continuous random variables**.

## 5.2 CDF for our uniform watch-time example

For $T\sim\operatorname{Uniform}(0,10)$:

$$
F_T(t)=\begin{cases}
0 & t<0,\\
\dfrac{t}{10} & 0\leq t\leq10,\\
1 & t>10.
\end{cases}
$$

Why is the middle piece $t/10$? Accumulated area from 0 to $t$ is $t\times0.1$.

**Examples:**

$$
F_T(4)=\frac4{10}=\boxed{0.40};\quad
F_T(8)=\frac8{10}=\boxed{0.80}.
$$

So:

$$
\begin{aligned}
P(4<T\leq8)&=F_T(8)-F_T(4)\\
&=0.80-0.40=\boxed{0.40}.
\end{aligned}
$$

To find the chance of *exceeding* 8 minutes, use a complement:

$$P(T>8)=1-F_T(8)=1-0.8=\boxed{0.2}.$$

## 5.3 CDFs for discrete variables are steps

Return to our two-video click distribution:

| Clicks $X$ | PMF $P(X=x)$ | CDF $F_X(x)$ |
|---:|---:|---:|
| 0 | 0.25 | 0.25 |
| 1 | 0.50 | 0.75 |
| 2 | 0.25 | 1.00 |

The full discrete CDF is:

$$
F_X(x)=\begin{cases}
0 & x<0,\\
0.25 & 0\leq x<1,\\
0.75 & 1\leq x<2,\\
1 & x\geq2.
\end{cases}
$$

For example, $F_X(1)=P(X\leq1)=P(X=0)+P(X=1)=0.75$.

Notice that the CDF *jumps* where positive discrete probability mass exists. The jump at $x=1$ is 0.50, exactly $P(X=1)$.

## 5.4 Interval endpoint trap: continuous vs discrete

For **any** distribution:

$$\boxed{P(a<X\leq b)=F_X(b)-F_X(a).}$$

For a **continuous** distribution, single points have zero probability, so $P(a\leq X\leq b)$ gives the same result.

For a **discrete** distribution, endpoints can matter. In general:

$$
P(a\leq X\leq b)=F_X(b)-P(X<a).
$$

Using the left-hand limit $F_X(a^-)$:

$$P(a\leq X\leq b)=F_X(b)-F_X(a^-).$$

**Concrete comparison using our click counts:**

$$
P(1<X\leq2)=P(X=2)=0.25=F_X(2)-F_X(1).
$$

But:

$$
P(1\leq X\leq2)=P(X=1)+P(X=2)=0.75.
$$

Using $F_X(2)-F_X(1)=0.25$ for this second question would **incorrectly exclude** the probability at 1.

## 5.5 Valid CDF properties

- $0\leq F_X(x)\leq1$.
- It is **nondecreasing**: increasing the threshold never removes previously included probability.
- It approaches 0 as $x\to-\infty$ and 1 as $x\to\infty$.
- It is **right-continuous**, even for distributions with jumps.
- Where a continuous CDF is differentiable, its derivative is the PDF: $f_X(x)=F_X'(x)$.

### Interview check

**Q:** $F_T(2)=0.25$, $F_T(5)=0.70$. Find $P(2<T\leq5)$.  
**A:** $0.70-0.25=\boxed{0.45}$.

# Lesson 06 — Expected Value, Variance, and Standard Deviation

## 6.1 Expected value: a probability-weighted average

Our two-video click PMF is:

| $x$ | $P(X=x)$ | $xP(X=x)$ |
|---:|---:|---:|
| 0 | 0.25 | $0\times0.25=0$ |
| 1 | 0.50 | $1\times0.50=0.50$ |
| 2 | 0.25 | $2\times0.25=0.50$ |

For a discrete variable:

$$\boxed{E[X]=\sum_x xP(X=x).}$$

Add the weighted outcomes:

$$
E[X]=0+0.5+0.5=\boxed{1\text{ click}}.
$$

This does **not** promise each user will click one video. It is the expected average across a large number of comparable, identically distributed observations when the relevant averaging assumptions hold.

**Second example with a noninteger expected count:**

Suppose $P(X=0)=0.50$, $P(X=1)=0.30$, and $P(X=2)=0.20$.

$$
E[X]=0(0.5)+1(0.3)+2(0.2)=0+0.3+0.4=\boxed{0.7}.
$$

Nobody clicks “0.7 videos” in one trial. A mean need not be a possible individual outcome.

## 6.2 Variance: how much outcomes fluctuate around the mean

Expected value alone does not describe variability. For the original distribution, $\mu=E[X]=1$.

For each outcome:

1. Subtract the mean: $x-1$.
2. Square the deviation: $(x-1)^2$.
3. Weight that squared deviation by its probability.
4. Add the contributions.

| $x$ | $P(X=x)$ | $x-\mu$ | $(x-\mu)^2$ | Weighted result |
|---:|---:|---:|---:|---:|
| 0 | 0.25 | -1 | 1 | 0.25 |
| 1 | 0.50 | 0 | 0 | 0 |
| 2 | 0.25 | +1 | 1 | 0.25 |

$$
\boxed{\operatorname{Var}(X)=E[(X-E[X])^2]=\sum_x(x-\mu)^2P(X=x).}
$$

Therefore:

$$
\operatorname{Var}(X)=0.25+0+0.25=\boxed{0.50\text{ clicks}^2}.
$$

Standard deviation brings the units back to clicks:

$$
\boxed{\operatorname{SD}(X)=\sqrt{0.50}\approx0.707\text{ clicks}}.
$$

## 6.3 Shortcut formula, with a complete calculation

Another mathematically equivalent formula is:

$$\boxed{\operatorname{Var}(X)=E[X^2]-(E[X])^2.}$$

First compute the expected square:

$$
\begin{aligned}
E[X^2]&=0^2(0.25)+1^2(0.50)+2^2(0.25)\\
&=0+0.50+1.00=1.50.
\end{aligned}
$$

Then subtract the squared mean:

$$
\operatorname{Var}(X)=1.50-1^2=\boxed{0.50}.
$$

For our alternative PMF with probabilities 0.50, 0.30, and 0.20:

$$
E[X]=0.7,\qquad E[X^2]=0+0.3+4(0.2)=1.1,
$$

so:

$$\operatorname{Var}(X)=1.1-(0.7)^2=1.1-0.49=\boxed{0.61}.$$

## 6.4 Expected value and variance for continuous variables

For a continuous variable, sums become areas (integrals):

$$
E[T]=\int_{-\infty}^{\infty}t f_T(t)\,dt.
$$

For $T\sim\operatorname{Uniform}(0,10)$, density $f_T(t)=0.1$:

$$
E[T]=\int_0^{10}0.1t\,dt
=0.1\left[\frac{t^2}{2}\right]_0^{10}
=0.1\times50=\boxed{5\text{ minutes}}.
$$

And:

$$
\begin{aligned}
E[T^2]&=0.1\int_0^{10}t^2dt\\
&=0.1\left[\frac{t^3}{3}\right]_0^{10}\\
&=\frac{100}{3}.
\end{aligned}
$$

Thus:

$$
\operatorname{Var}(T)=\frac{100}{3}-25=\boxed{\frac{25}{3}\approx8.33\text{ min}^2}.
$$

$$\operatorname{SD}(T)=\sqrt{25/3}\approx\boxed{2.887\text{ minutes}}.$$

If calculus is not yet comfortable, retain the intuition: *weight each possible outcome by its probability density, accumulated across the entire range*.

## 6.5 Why this matters to a senior engineer

Two recommendation models can both average one click per user while having very different variance. One produces consistent results; the other produces many zeros and occasional high click counts. Both averages can be identical even if the product experience differs.

Useful rules:

$$
E[aX+b]=aE[X]+b,
$$

$$
\operatorname{Var}(aX+b)=a^2\operatorname{Var}(X),
$$

and, importantly,

$$
E[X+Y]=E[X]+E[Y]\quad\text{even without independence}.
$$

Variance of a sum is different:

$$
\operatorname{Var}(X+Y)=\operatorname{Var}(X)+\operatorname{Var}(Y)+2\operatorname{Cov}(X,Y).
$$

Only when $X$ and $Y$ have zero covariance (including when independent) can the covariance term be omitted.

**Connection to Chapter 1:** These are properties of *theoretical distributions*. Sample variance computed from finite observed data often uses $n-1$ as a correction when estimating a population variance. **Do not insert $n-1$ into the definition of the theoretical variance above.**

### Interview check

**Q:** Can the expected number of clicks equal 0.7?  
**A:** Yes. A long-run average can be fractional even when individual counts are integers.

# Lesson 07 — Bernoulli Distribution: One Binary Trial

## 7.1 Start with one recommendation

Suppose a recommendation model predicts that the probability of clicking a particular video is 30%.

Define:

$$
X=\begin{cases}
1 & \text{Click},\\
0 & \text{No click}.
\end{cases}
$$

Then:

$$P(X=1)=0.3,\qquad P(X=0)=0.7.$$

This is a **Bernoulli distribution**, written:

$$\boxed{X\sim\operatorname{Bernoulli}(p),\quad p=0.3.}$$

“Success” is conventionally coded as 1, but it is only a label. In fraud detection, 1 may mean **fraud**. Success does not need to be a desirable event.

## 7.2 Bernoulli is a special discrete distribution

The PMF has exactly two values:

| Outcome $x$ | Probability |
|---:|---:|
| 0 | $1-p$ |
| 1 | $p$ |

A compact expression gives both rows:

$$\boxed{P(X=x)=p^x(1-p)^{1-x},\qquad x\in\{0,1\}.}$$

**Verify rather than memorize:**

- If $x=1$: $p^1(1-p)^0=p$.
- If $x=0$: $p^0(1-p)^1=1-p$.

A Bernoulli variable can have $p=0$ or $p=1$; these are deterministic endpoint cases.

## 7.3 Derive Bernoulli expected value

Using the PMF:

$$
\begin{aligned}
E[X]&=0\cdot(1-p)+1\cdot p\\
&=\boxed{p}.
\end{aligned}
$$

For $p=0.3$, the expected click count per single impression is 0.3. At scale, the expected total across 1,000 comparable impressions is $1000\times0.3=300$ clicks, although an observed total need not be exactly 300.

## 7.4 Derive Bernoulli variance

For a binary variable, $X^2=X$, since both $0^2=0$ and $1^2=1$.

So:

$$E[X^2]=E[X]=p.$$

Using $\operatorname{Var}(X)=E[X^2]-(E[X])^2$:

$$
\begin{aligned}
\operatorname{Var}(X)&=p-p^2\\
&=\boxed{p(1-p)}.
\end{aligned}
$$

For $p=0.3$:

$$\operatorname{Var}(X)=0.3\times0.7=\boxed{0.21}.$$

Interpretation:

- At $p=0$: the outcome is always 0, variance 0.
- At $p=1$: the outcome is always 1, variance 0.
- At $p=0.5$: the outcomes are most uncertain; variance is maximal at $0.25$.

## 7.5 Connect Bernoulli to Logistic Regression

A logistic regression model predicts $p_i=P(Y_i=1\mid\mathbf{x}_i)$, often through:

$$p_i=\sigma(\mathbf{w}^T\mathbf{x}_i+b).$$

With a binary label $y_i\in\{0,1\}$, the Bernoulli probability assigned to that observed label is:

$$P(Y_i=y_i\mid\mathbf{x}_i)=p_i^{y_i}(1-p_i)^{1-y_i}.$$

Taking negative log gives **binary cross-entropy** for one observation:

$$
\boxed{L_i=-\big[y_i\log p_i+(1-y_i)\log(1-p_i)\big].}
$$

**Worked intuition:** If the true label is $y=1$:

- Predict $p=0.8$: $L=-\log(0.8)\approx0.223$.
- Predict $p=0.1$: $L=-\log(0.1)\approx2.303$.

The model is penalized much more for being confidently wrong.

**Important:** The fact that a model outputs a Bernoulli probability does *not* guarantee that its predicted probabilities are calibrated. Calibration must be evaluated from observed outcomes.

### Interview check

**Q:** Fraud follows $Y\sim\operatorname{Bernoulli}(0.02)$, where 1 means fraud. What is $P(Y=0)$?  
**A:** $1-0.02=\boxed{0.98}$, or 98%.

# Lesson 08 — Binomial Distribution: Repeated Bernoulli Trials

## 8.1 From one click to several clicks

Bernoulli answers: “Does one recommendation get clicked?”

Binomial answers: **“How many clicks occur among a fixed number of independent recommendations having the same click probability?”**

Take three recommendations, each independently clicked with probability $p=0.5$.

Let $X$ count the total clicks. We want $P(X=2)$.

Represent click by C and no click by N:

| Sequence | Click count |
|---|---:|
| NNN | 0 |
| CNN | 1 |
| NCN | 1 |
| NNC | 1 |
| CCN | 2 |
| CNC | 2 |
| NCC | 2 |
| CCC | 3 |

Every ordered sequence has probability $(0.5)^3=0.125$.

Exactly two clicks occur in three sequences: CCN, CNC, NCC.

$$P(X=2)=3\times0.125=\boxed{0.375=37.5\%}.$$

## 8.2 Where the formula comes from

If an ordered sequence has $k$ successes and $n-k$ failures, its probability (given independent trials and common success probability $p$) is:

$$p^k(1-p)^{n-k}.$$

But there are multiple arrangements of those successes. The number of arrangements is:

$$\binom nk=\frac{n!}{k!(n-k)!}.$$

Multiply arrangement count by the probability of any one arrangement:

$$\boxed{P(X=k)=\binom nk p^k(1-p)^{n-k}.}$$

Notation:

$$\boxed{X\sim\operatorname{Binomial}(n,p).}$$

**Parameter meanings:**

- $n$: fixed number of trials, a nonnegative integer.
- $p$: common success probability per trial.
- $k$: success count being evaluated, $k\in\{0,1,\ldots,n\}$.

## 8.3 Complete worked example with the formula

Three trials, two successes, $p=0.5$:

$$
\begin{aligned}
P(X=2)
&=\binom32(0.5)^2(0.5)^1\\
&=\frac{3!}{2!1!}\times0.25\times0.5\\
&=3\times0.125\\
&=\boxed{0.375}.
\end{aligned}
$$

The complete PMF is:

| Clicks $k$ | $P(X=k)$ |
|---:|---:|
| 0 | 0.125 |
| 1 | 0.375 |
| 2 | 0.375 |
| 3 | 0.125 |
| **Total** | **1.000** |

**At least one click** can be solved quickly by complement:

$$
P(X\geq1)=1-P(X=0)=1-(0.5)^3=\boxed{0.875}.
$$

## 8.4 A less symmetric example: 10 impressions, 30% conversion

Suppose 10 independent ad impressions each convert with the same probability 0.30.

Find the probability of **exactly 3 conversions**:

$$X\sim\operatorname{Binomial}(10,0.3).$$

$$
\begin{aligned}
P(X=3)
&=\binom{10}{3}(0.3)^3(0.7)^7\\
&=120\times0.027\times0.0823543\\
&\approx\boxed{0.2668=26.68\%}.
\end{aligned}
$$

This is not the same as “30% of the impressions convert with certainty.” It is the probability of seeing the count 3 in one batch of 10 under the model.

## 8.5 Derive Binomial mean and variance from Bernoulli

A Binomial count can be written as the sum of $n$ Bernoulli indicators:

$$X=X_1+X_2+\cdots+X_n.$$

Each has $E[X_i]=p$ and $\operatorname{Var}(X_i)=p(1-p)$.

Using linearity of expectation:

$$\boxed{E[X]=np}.$$

Because these trials are independent, their variances add:

$$\boxed{\operatorname{Var}(X)=np(1-p)}.$$

For $n=10$ and $p=0.3$:

$$
E[X]=10(0.3)=\boxed{3},\qquad
\operatorname{Var}(X)=10(0.3)(0.7)=\boxed{2.1}.
$$

Note that expected count 3 does not imply count 3 occurs most of the time, though 3 is one of the more likely counts in this example.

## 8.6 Assumptions: where Binomial can fail in production

A standard Binomial model requires:

1. **Fixed $n$:** the number of trials is decided or conditioned on.
2. **Binary outcome:** each trial is coded success/failure.
3. **Independence:** one trial does not alter the probabilities of the others.
4. **Identical $p$:** the success chance is the same for each trial.

Failures to watch for:

- One user receives sequential recommendations; prior clicks influence later behavior → independence questionable.
- Impressions go to people with different predicted click probabilities → common $p$ questionable. Independent unequal-probability trials lead to a **Poisson-binomial**, not ordinary Binomial, count distribution.
- Conversion probability shifts during a campaign → constant $p$ questionable.

The model is useful *when the assumptions approximate the business process*, not merely because the target is a count.

### Interview check

**Q:** Four independent trials each succeed with probability 0.5. What is the probability of exactly two successes?  
**A:** $\binom42(0.5)^2(0.5)^2=6/16=\boxed{0.375}$.

# Lesson 09 — Poisson Distribution: Counting Arrivals

## 9.1 The problem is different from Binomial

A backend service receives incoming requests. Monitoring estimates a **constant average rate of 2 requests per second** for a short period.

The manager asks: “What is the probability of exactly 3 requests during the next second?”

Unlike the Binomial setup, we do **not** have a prespecified fixed number of yes/no trials. We are counting *arrivals in an interval*.

The Poisson distribution is a useful model **if** events occur according to a suitable constant-rate, independent-arrival process.

Define:

$$X=\text{Number of requests in the next 1 second}.$$

If the expected number arriving in that interval is $\lambda=2$:

$$\boxed{X\sim\operatorname{Poisson}(2).}$$

Possible values: $0,1,2,3,\ldots$, with no fixed finite upper bound.

## 9.2 Rate vs expected count: get the units right

There are two related concepts:

- Arrival **rate** $r$: e.g. 2 requests per second.
- Expected count **within an interval of length $t$**: $\lambda=rt$.

For a one-second interval:

$$\lambda=(2\text{ requests/sec})(1\text{ sec})=2.$$

For a five-second interval:

$$\lambda=(2\text{ requests/sec})(5\text{ sec})=10.$$

Always match $\lambda$ to the interval. A common interview error is using 2 as the expected count for every window, regardless of duration.

## 9.3 The Poisson PMF

$$\boxed{P(X=k)=\frac{e^{-\lambda}\lambda^k}{k!},\quad k=0,1,2,\ldots}$$

Where:

- $e\approx2.71828$ is the natural exponential constant.
- $\lambda\geq0$ is the expected count for the interval.
- $k!$ is factorial; $0!=1$.

## 9.4 Exactly three requests: full worked calculation

Let $\lambda=2$, $k=3$.

$$
\begin{aligned}
P(X=3)
&=\frac{e^{-2}2^3}{3!}\\
&=\frac{0.135335\times8}{6}\\
&=\frac{1.08268}{6}\\
&\approx\boxed{0.180447=18.04\%}.
\end{aligned}
$$

That probability does not say three requests *must* arrive in 18% of every small batch of seconds. It is a probability implied by the model.

## 9.5 Zero arrivals, at least one arrival, at least three arrivals

**Zero arrivals:**

$$
P(X=0)=\frac{e^{-2}2^0}{0!}=\boxed{e^{-2}\approx0.1353}.
$$

**At least one arrival:** Use the complement of zero:

$$
P(X\geq1)=1-P(X=0)=1-0.1353=\boxed{0.8647}. 
$$

**At least three arrivals:** Use the complement of 0, 1, or 2:

$$
\begin{aligned}
P(X\geq3)
&=1-[P(X=0)+P(X=1)+P(X=2)]\\
&=1-[0.135335+0.270671+0.270671]\\
&\approx\boxed{0.3233=32.33\%}.
\end{aligned}
$$

The complement avoids summing infinitely many values $k=3,4,5,\ldots$.

## 9.6 Mean and variance

For a Poisson distribution:

$$
\boxed{E[X]=\lambda},\qquad
\boxed{\operatorname{Var}(X)=\lambda}.
$$

For $\lambda=2$, mean count 2 and variance 2 (counts squared). Its standard deviation is $\sqrt2\approx1.414$.

This equality is a signature of the ideal Poisson model, not a law that all real arrival-count data must obey.

## 9.7 Connection with Binomial

Under suitable limiting conditions, a Binomial count approaches a Poisson distribution:

$$n\to\infty,\quad p\to0,\quad np\to\lambda.$$

Intuition: A **very large number of tiny independent opportunities**, each with a small event probability, can produce a moderate number of arrivals overall. This is an approximation, not permission to use Poisson for arbitrary counts.

## 9.8 Real production diagnostic: bursts and overdispersion

The simple Poisson model assumes a homogeneous rate and an appropriate independence structure. It can fail when:

- A livestream causes synchronized requests.
- Traffic rises and falls sharply through the day.
- Retries cause correlated bursts.
- A shared network outage changes arrival patterns.

A quick empirical diagnostic is to compare sample variance and mean of counts across equal-length windows:

$$\text{Fano factor}=\frac{\text{count variance}}{\text{count mean}}.$$

A value much larger than 1 may suggest *overdispersion* relative to Poisson. But this alone is not a proof of any specific alternative model; unequal rates and dependence can both cause it.

**Senior engineer distinction:** Poisson arrivals describe *how many requests arrive*. They do not directly describe request processing time, queueing delays, or service-time distributions.

### Interview check

**Q:** At 3 expected arrivals per second, what's the probability of zero arrivals during one second?  
**A:** $e^{-3}\approx\boxed{0.0498=4.98\%}$.

# Lesson 10 — Normal Distribution: Symmetric Variation

## 10.1 The bell-shaped idea

Suppose—**for learning, not as an empirical claim**—that daily watch time of a carefully selected group of comparable users is Normally distributed with:

- Mean $\mu=60$ minutes.
- Standard deviation $\sigma=10$ minutes.

We write:

$$\boxed{T\sim N(60,100).}$$

**Why 100?** Normal notation uses $N(\mu,\sigma^2)$, so the second parameter is **variance**: $10^2=100$.

The Normal distribution is continuous, symmetric, and bell-shaped:

- Centered at its mean $\mu$.
- Mean = median = mode.
- The density is highest at $\mu$.
- A larger $\sigma$ makes the curve wider and lower; a smaller $\sigma$ makes it narrower and higher.
- The total area under the curve is 1.

## 10.2 Understand the famous 68–95–99.7 rule

For a Normal variable, approximately:

| Interval | Our example | Probability |
|---|---|---:|
| $\mu\pm1\sigma$ | 50 to 70 minutes | 68.27% |
| $\mu\pm2\sigma$ | 40 to 80 minutes | 95.45% |
| $\mu\pm3\sigma$ | 30 to 90 minutes | 99.73% |

The shorthand “68–95–99.7” is deliberately rounded.

**Meaning of ±2 SD:** In repeated draws from this exact Normal model, about 95% of values lie within two standard deviations of the mean. It does not say 95% of *any arbitrary dataset* must lie in that range.

## 10.3 Z-scores: express a value in standard-deviation units

You already know the z-score from descriptive statistics:

$$\boxed{Z=\frac{T-\mu}{\sigma}}.$$

Our mean is 60 and standard deviation is 10.

| Watch time $T$ | Calculation | Z-score | Interpretation |
|---:|---|---:|---|
| 50 | $(50-60)/10$ | −1 | One SD below mean |
| 60 | $(60-60)/10$ | 0 | At the mean |
| 70 | $(70-60)/10$ | +1 | One SD above mean |
| 80 | $(80-60)/10$ | +2 | Two SDs above mean |

When $T$ is Normal, $Z$ follows the *standard Normal distribution*:

$$Z\sim N(0,1).$$

The standard Normal CDF is usually written $\Phi(z)$.

## 10.4 Probability of watching longer than 80 minutes

Step 1: Standardize the threshold.

$$z=\frac{80-60}{10}=2.$$

Step 2: Find cumulative probability up to $z=2$:

$$\Phi(2)\approx0.97725.$$

Step 3: Take the complement:

$$
\begin{aligned}
P(T>80)&=P(Z>2)\\
&=1-\Phi(2)\\
&=1-0.97725\\
&=\boxed{0.02275\approx2.28\%}.
\end{aligned}
$$

The 68–95–99.7 rule gives a rough 2.5% one-sided tail beyond +2 SD; the precise Normal probability is about **2.28%**. Understand the difference between an approximation and a more accurate CDF lookup.

## 10.5 Probability between 50 and 80 minutes

Step 1: Turn endpoints into z-scores:

$$z_{50}=-1,\qquad z_{80}=+2.$$

Step 2: Subtract Normal CDF values:

$$
\begin{aligned}
P(50<T<80)
&=\Phi(2)-\Phi(-1)\\
&\approx0.97725-0.15866\\
&=\boxed{0.81859\approx81.86\%}.
\end{aligned}
$$

This is the same CDF subtraction principle from Lesson 05.

## 10.6 The Normal PDF (for reference)

$$
\boxed{f_T(t)=\frac1{\sigma\sqrt{2\pi}}
\exp\left(-\frac{(t-\mu)^2}{2\sigma^2}\right).}
$$

Conceptually:

- $t-\mu$ measures distance from center.
- Squaring makes equal positive/negative distances equally important.
- $\sigma$ controls spread.
- The exponential makes the density decrease smoothly as distance grows.
- The front coefficient normalizes total area to 1.

**Do not confuse** this density value $f_T(t)$ with $P(T=t)$, which is zero for a Normal variable.

## 10.7 Why Normal is powerful—and where it is inappropriate

Normal models are useful for certain errors, residuals, and sampling-distribution approximations, **after their assumptions are examined**.

But real watch time often has:

- A nonnegative lower bound.
- A long right tail from heavy viewers.
- Many short sessions and fewer very long sessions.

A Normal model assigns some probability to **negative** watch times, which are impossible. If that probability is material or the data are heavily skewed, another model may be more sensible (for example, lognormal or gamma for positive measurements).

**Central Limit Theorem distinction:** In many settings, averages of sufficiently large samples can be *approximately Normal* even when individual observations are not. That **does not imply the raw observations themselves are Normal**. We study the CLT properly in Statistical Inference.

### Interview checks

**Q:** If $X\sim N(60,100)$, is SD 100?  
**A:** No. Variance is 100; SD is 10.

**Q:** Is $P(X=60)$ positive?  
**A:** No. Normal is continuous, so $P(X=60)=0$. Probability applies to intervals.

# Lesson 11 — Exponential Distribution: Waiting for the Next Arrival

## 11.1 The bridge from Poisson

Poisson asks **how many** requests arrive in an interval.

Exponential asks **how long until the next** request arrives, under the same constant-rate Poisson-process assumptions.

Suppose arrivals occur at rate:

$$r=2\text{ requests/second}.$$

Let $T$ be the waiting time in seconds from an arbitrary starting point until the next arrival. Then:

$$\boxed{T\sim\operatorname{Exponential}(r=2).}$$

In many textbooks the rate is written $\lambda$. We write $r$ here to make the **rate per unit time** explicit and avoid confusion with the Poisson *expected count per interval*.

## 11.2 Expected waiting time

For an Exponential distribution in the **rate parameterization**:

$$\boxed{E[T]=\frac1r}.$$

For 2 arrivals per second:

$$E[T]=\frac12=\boxed{0.5\text{ seconds}}.$$

If the rate were 4 per second:

$$E[T]=\frac14=\boxed{0.25\text{ seconds}=250\text{ ms}}.$$

Higher average arrival rate means shorter expected waiting time.

**Not every gap is 0.5 seconds.** Waiting times vary, and an exponential distribution is right-skewed.

## 11.3 Survival probability: waiting longer than a threshold

If waiting longer than $t$ means zero requests arrive during the next $t$ seconds, then the Poisson zero-count result gives:

$$
P(T>t)=P(N(t)=0)=e^{-rt}.
$$

So:

$$\boxed{P(T>t)=e^{-rt},\qquad t\geq0}.$$

This is the **survival function**. It gives the probability the wait exceeds $t$.

**Example: Probability of waiting more than 1 second** when $r=2$:

$$
P(T>1)=e^{-2(1)}=e^{-2}\approx\boxed{0.1353=13.53\%}.
$$

## 11.4 CDF: arriving within the threshold

Use the complement:

$$
\begin{aligned}
P(T\leq t)&=1-P(T>t)\\
&=\boxed{1-e^{-rt}}.
\end{aligned}
$$

For arrival within one second:

$$
P(T\leq1)=1-e^{-2}\approx\boxed{0.8647=86.47\%}.
$$

The Exponential CDF is:

$$F_T(t)=\begin{cases}
0 & t<0,\\
1-e^{-rt} & t\geq0.
\end{cases}$$

Its PDF for $t\geq0$ is:

$$\boxed{f_T(t)=re^{-rt}}.$$

The PDF is obtained by differentiating the CDF; probabilities still come from intervals, not exact time points.

## 11.5 Probability of a waiting-time interval

Find the probability that the next request arrives **after 0.2 seconds but no later than 0.7 seconds**:

$$
P(0.2<T\leq0.7)=F_T(0.7)-F_T(0.2).
$$

Using $F_T(t)=1-e^{-2t}$:

$$
\begin{aligned}
P(0.2<T\leq0.7)
&=(1-e^{-1.4})-(1-e^{-0.4})\\
&=e^{-0.4}-e^{-1.4}\\
&\approx0.67032-0.24660\\
&=\boxed{0.42372\approx42.37\%}.
\end{aligned}
$$

Again, notice how CDF subtraction unifies the chapter.

## 11.6 Variance and the surprising difference between mean and median

For an Exponential distribution:

$$
\boxed{\operatorname{Var}(T)=\frac1{r^2}},\qquad
\boxed{\operatorname{SD}(T)=\frac1r}.
$$

For $r=2$:

- Mean = 0.5 seconds.
- Variance = 0.25 seconds squared.
- Standard deviation = 0.5 seconds.

What about the **median** waiting time (the time by which 50% of arrivals have occurred)? Solve:

$$
F_T(m)=0.5
\Rightarrow1-e^{-rm}=0.5
\Rightarrow e^{-rm}=0.5.
$$

Thus:

$$\boxed{m=\frac{\ln2}{r}}.$$

At rate 2:

$$m=\frac{0.6931}{2}\approx\boxed{0.3466\text{ seconds}}.$$

The median is less than the mean because the distribution has a long right tail. This is an excellent reminder that **mean and median are not generally equal**.

## 11.7 Memorylessness—understand the actual statement

The Exponential distribution has a *memoryless* property:

$$\boxed{P(T>s+t\mid T>s)=P(T>t)}.$$

Read it carefully: **conditional on having already waited $s$ seconds with no arrival, the probability of waiting another $t$ seconds is unchanged.**

Example: We have already waited 2 seconds without a request. Under the constant-rate Poisson model, the probability of waiting more than one *additional* second is still:

$$e^{-2(1)}=\boxed{13.53\%}.$$

This does not say elapsed time is irrelevant for arbitrary real waiting-time processes. It is a consequence of this specific distribution.

## 11.8 Rate vs scale: a common library/interview trap

Some references parameterize an Exponential distribution using its **scale** $\theta=1/r$, not its rate $r$.

| Parameterization | Parameter value in our example | Mean |
|---|---:|---:|
| Rate $r$ | $2\text{ per second}$ | $1/r=0.5$ sec |
| Scale $\theta$ | $0.5\text{ sec}$ | $\theta=0.5$ sec |

Both describe the same distribution. Always check what a formula or software interface expects.

## 11.9 Production caveat

Real traffic often violates a simple constant-rate Poisson process: retries, shared events, rate limiting, and time-of-day effects create changes and correlations. Also, **time to the next arrival** is not the same random variable as **request service time** or **end-to-end API response latency**. Do not automatically assign an Exponential distribution to all three.

### Interview check

**Q:** At 4 requests per second, what is expected time until the next request?  
**A:** $1/4=\boxed{0.25\text{ seconds}}$.

# Lesson 12 — Revision, Model Selection, and Assessment

## 12.1 One decision map to connect the whole chapter

Start by identifying **what the business question measures**.

```text
What does the random variable represent?
|
+-- Count / binary outcome (discrete)
|   |
|   +-- One success/failure outcome?               -> Bernoulli
|   +-- Successes in fixed n independent trials
|   |     with the same probability?               -> Binomial
|   +-- Arrivals in an interval under
|         a constant-rate Poisson process?        -> Poisson
|
+-- Measurement / waiting time (continuous)
    |
    +-- Symmetric bell-shaped measurements?       -> Normal (if reasonable)
    +-- Time to next event in a
          constant-rate Poisson process?          -> Exponential

Regardless of distribution:
- Discrete exact probability -> PMF.
- Continuous interval probability -> area under PDF.
- Probability at/below threshold -> CDF.
- Long-run average -> expected value.
- Fluctuation around average -> variance and SD.
```

The arrows indicate *candidate models based on assumptions*, not automatic rules. Other distributions may fit better.

## 12.2 Master comparison table

| Distribution | Type | Parameters | Main question | Mean | Variance |
|---|---|---|---|---|---|
| Bernoulli | Discrete | $p$ | Does one trial succeed? | $p$ | $p(1-p)$ |
| Binomial | Discrete | $n,p$ | Number of successes in fixed $n$ trials? | $np$ | $np(1-p)$ |
| Poisson | Discrete | $\lambda$ expected count | Number of arrivals in interval? | $\lambda$ | $\lambda$ |
| Normal | Continuous | $\mu,\sigma^2$ | Symmetric variability around a mean? | $\mu$ | $\sigma^2$ |
| Exponential (rate) | Continuous | $r$ events per time | Wait until next event? | $1/r$ | $1/r^2$ |

### Formula bank, with meanings

| Formula | Use |
|---|---|
| $p_X(x)=P(X=x)$ | Exact discrete-value probability (PMF) |
| $P(a\leq X\leq b)=\int_a^b f_X(x)dx$ | Area under continuous PDF |
| $F_X(x)=P(X\leq x)$ | CDF at a threshold |
| $P(a<X\leq b)=F_X(b)-F_X(a)$ | CDF difference; valid for any distribution |
| $E[X]=\sum_x xP(X=x)$ | Discrete expected value |
| $\operatorname{Var}(X)=E[X^2]-(E[X])^2$ | Shortcut variance |
| $p^x(1-p)^{1-x}$ | Bernoulli PMF, $x=0,1$ |
| $\binom nk p^k(1-p)^{n-k}$ | Binomial PMF |
| $e^{-\lambda}\lambda^k/k!$ | Poisson PMF |
| $z=(x-\mu)/\sigma$ | Standardizing to a Normal z-score |
| $P(T>t)=e^{-rt}$ | Exponential survival probability |
| $P(T\leq t)=1-e^{-rt}$ | Exponential CDF |

## 12.3 How to pick a distribution in production: seven checks

1. **Define the observation unit.** A click per impression, clicks per user, and clicks per session are not interchangeable.
2. **Define the measurement window.** “Per second” and “per five minutes” change expected counts.
3. **Check the support.** Can the variable be negative? Integer only? Capped? Are there structural zeros?
4. **Inspect the shape.** Look for skew, tails, multiple peaks, spikes at zero, and changing behavior over time.
5. **Test assumptions.** Independence, constant success probability, stationary arrival rate, and Normal symmetry are assumptions—not guarantees.
6. **Assess out-of-sample fit.** Use holdout periods, distribution comparisons, residual checks, or calibration suited to the use case.
7. **Interpret tail risk.** Average load alone does not capture bursts, p95/p99 latency, or rare events.

**Example production question:** “We observe a mean of 100 requests/s; can we size capacity for exactly 100 each second?”  
**Answer:** No. Means do not bound variance or tail peaks. Examine arrival-count distributions over multiple resolutions, correlated spikes, autoscaling behavior, service capacity, and user-facing latency objectives.

## 12.5 High-value interview traps and short answers

**Q: Does a PDF value of 1.5 violate probability rules?**  
**A:** No. Density may exceed 1; total area must equal 1.

**Q: Is $P(X=3)=0$ true for all random variables?**  
**A:** No. For a continuous model, exact-point probability is zero; for a discrete model it may be positive.

**Q: Can a CDF decrease?**  
**A:** No. It is nondecreasing because raising the threshold can only include more outcomes.

**Q: Is the sample mean exactly equal to expected value?**  
**A:** Not necessarily. Expected value is a property of the distribution; sample mean is calculated from observed data and fluctuates between samples.

**Q: Can variance be negative?**  
**A:** No. It averages squared deviations with nonnegative weights.

**Q: Does Bernoulli's “success” label mean a favorable outcome?**  
**A:** No. It is whatever event has been coded 1.

**Q: Does Binomial work if each user has a different click probability?**  
**A:** Not as a standard common-$p$ Binomial model. Under independent unequal probabilities, the success count follows a Poisson-binomial distribution.

**Q: If Poisson has mean 2, must exactly 2 events occur?**  
**A:** No. The mean describes the average, not a guaranteed interval count.

**Q: If a model is Normal, does its second parameter represent SD?**  
**A:** Usually $N(\mu,\sigma^2)$ uses variance. Check parameterization in any source or software package.

**Q: Can the average of non-Normal values be approximately Normal?**  
**A:** Often, under suitable conditions and with sufficiently large samples; this is related to the CLT. It does not make the original data Normal.

**Q: Is an Exponential arrival-wait model the same as an API response-time model?**  
**A:** No. Interarrival time and service/response time are different quantities.

**Q: Is an Exponential distribution memoryless?**  
**A:** Yes: $P(T>s+t\mid T>s)=P(T>t)$, under its assumptions.

Probability distributions are a language for uncertainty. Start by defining **what is random** and **what a value means**. Then ask whether you need exact-value probability, interval probability, cumulative probability, a long-run mean, or a measure of spread.
